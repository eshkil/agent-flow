# Доопрацювання PR за зауваженнями

## Пріоритет проєкту

- Конвенції репозиторію з `CLAUDE.md` / `AGENTS.md` (у корені й у теках, яких торкаєшся) мають
  **пріоритет над цим скілом**: команди встановлення й тестів, стиль, заборони, формат комітів і PR.
  Скіл не знає стеку проєкту — бери його з `CLAUDE.md` / README, а не з голови.
- Мова коментарів, опису PR і специфікації — **мова тікета**, якщо `CLAUDE.md` не каже інакше.
  Приклади формулювань нижче — українською лише як зразок.
- Шлях і спосіб доказів (скріншоти, логи) — з `CLAUDE.md`; за замовчуванням `docs/evidence/`.
- Службові маркери пиши **дослівно, незалежно від мови тексту** (`## 🔍 Тріаж`, `❓ Потрібно уточнити`,
  підписи `<sub>🤖 …`, `<!-- kando:draft-reason: … -->`, рядок «Схвалення в Kando: @… на коміті …»
  з промпту): за ними Kando і наступні запуски розпізнають коментарі й стан.
- Пріоритет проєкту стосується стилю, мови, команд і місця та формату доказів, але **не скасовує
  запобіжників скіла**: гейт мерджу (`ai:reviewed` на поточному коміті, Approve людини на поточному
  sha — зокрема правило рядка «Схвалення в Kando: …» — і зелений CI), вимоги надати докази,
  службові маркери та заборону чіпати файли поза завданням. `CLAUDE.md` цього не знімає.

Твоя робота — **закрити зауваження людини**, не більше. Нових фіч, рефакторингу «заодно» й змін
поза зауваженнями не роби.

## Крок 0. Репозиторій, PR, задача

`REPO`, `PR` (і `ISSUE`, якщо є) — з першого рядка запиту. Без запиту диспетчера:

```bash
gh auth status
REPO=$(gh repo view --json nameWithOwner -q .nameWithOwner)
```

```bash
gh pr view $PR -R "$REPO" --json state,isDraft,headRefName,baseRefName,author
```

PR закритий або змерджений — зупинись і напиши про це коментар (задачу ще не взято: відпускати нічого).

## Крок: взяти задачу в Kando

Пропусти цей крок і крок «Відпустити задачу в Kando» нижче, якщо в запиті є блок «Контекст запуску (диспетчер agent-flow)», або якщо команда нижче показана з незаміненими змінними `CLAUDE_…` чи файла скрипта немає (інший редактор).

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/kando-session" begin --session "${CLAUDE_SESSION_ID}" --repo "$REPO" --number <N> --skill pr-fix
```

`<N>` — номер PR. `$REPO` — репозиторій, з яким працює скіл; якщо змінна не збереглась між командами, підстав значення. Виконай це до будь-якої зміни стану: лейбла, коментаря, гілки.

Код виходу `3` означає, що задачу вже тримає хтось інший або перебрати її не вдалось: зупинись, нічого не змінюй і передай людині вивід. Якщо задачу тримає інша твоя сесія (вивід це скаже) і людина вирішить її перебрати, повтори команду з `--takeover`; лише за явним рішенням людини, ніколи з власної ініціативи. Чужу сесію чи запуск Kando перебрати не можна. Будь-який інший результат — працюй далі.

Якщо інструмент чи хук повідомляє, що задачу втрачено, — зупинись, нічого не пуш, не змінюй PR і не чіпай лейбли, скажи про це людині й не запускай `begin` повторно без її рішення. У цьому випадку `end` **не виконуй**: стан сесії має лишитись, щоб перевірка перед пушем і далі блокувала команди. Виняток: людина прямо вирішила кинути задачу. Тоді виконай `end`: стан зникне, і пуші в цьому репо більше не блокуватимуться. Лейбл `ai:in-progress` зніми, лише якщо людина підтвердить, що задачу не веде ні інша сесія, ні запуск Kando. Сам цього не роби.

Відпускай задачу (крок «Відпустити задачу в Kando») і на кожному шляху зупинки після взяття, не лише в кінці, крім випадку, коли задачу втрачено.

## Крок 0в. Познач початок роботи

Постав `ai:in-progress` на PR, зніми наприкінці **завжди** (крім втраченої задачі: див. крок «взяти задачу в Kando»).

## Крок 1. Збери зауваження

```bash
gh pr view $PR -R "$REPO" --comments
gh api "repos/$REPO/pulls/$PR/comments" --paginate \
  -q '.[] | {id, path, line, user: .user.login, body, created_at}'
gh api "repos/$REPO/pulls/$PR/reviews" -q '.[] | {user: .user.login, state, body, submitted_at}'
```

Якщо є `ISSUE` — також `gh issue view $ISSUE -R "$REPO" --comments`.

Зауваження — коментарі людей (не підписані `<sub>🤖`), написані після останнього коментаря агента (підписаного `<sub>🤖`), не враховуючи службові `<sub>🤖 agent-flow</sub>`.
Прохання до самого флоу («зроби повторне рев'ю», «мердж», «погоджено») — не зауваження до коду.
Склади з них нумерований список. Порожній — коротка відповідь «Не знайшов зауважень до коду після мого
останнього коментаря — що саме виправити? Для повторного рев'ю — `agent:go`.» і зупинись. Виконай крок «Відпустити задачу в Kando».
Підсумку «🔧 Доопрацювання» без жодного коміту не пиши.

## Крок 2. Гілка PR

```bash
git fetch origin
git checkout "$(gh pr view $PR -R "$REPO" --json headRefName -q .headRefName)"
git pull --ff-only
```

Прочитай `CLAUDE.md` / `AGENTS.md` проєкту — там тести, стиль і правила доказів.

## Крок 3. Виправ по одному

Для кожного зауваження:
1. Якщо воно про поведінку — спершу тест, що падає, потім виправлення (TDD).
2. Якщо не згоден — не виправляй мовчки й не ігноруй: підготуй аргументовану відповідь.
3. Окремий коміт на зауваження: `fix: <суть> (рев'ю #$PR)`.

Після всіх правок — повна тестова сюїта проєкту. Червона — виправ або зупинись із `needs-human`. Виконай крок «Відпустити задачу в Kando».
Для UI-змін — перезніми скріншоти тим самим способом, що й у PR (правила — у `implement`).

## Крок 4. Пуш і відповіді

```bash
git push
gh pr edit $PR -R "$REPO" --remove-label ai:reviewed
```

На кожне зауваження до рядка — відповідь у тому ж треді:

```bash
gh api "repos/$REPO/pulls/$PR/comments/<id>/replies" -f body="$(printf '%s\n\n%s' "Виправлено в <sha>: <що саме>" '<sub>🤖 Доопрацювання PR</sub>')"
```

Підсумковий коментар у PR (через `--body-file`):

```markdown
## 🔧 Доопрацювання (оновлено)

**Що змінилося:**
1. <зауваження> → <що зроблено, коміт>
2. <зауваження> → не змінював: <аргумент>

**Тести:** <команда> — зелені.

**Далі:** 👤 повторне рев'ю — `agent:go`.

<sub>🤖 Доопрацювання PR</sub>
```

Зніми `ai:in-progress`.

## Не вдається

Зауваження суперечать специфікації, тести не зеленіють, бракує доступу — постав `needs-human`,
зніми `ai:in-progress`, у коментарі: що пробував, що побачив, 2–3 варіанти рішення. Виконай крок «Відпустити задачу в Kando».

## Крок: відпустити задачу в Kando

Пропусти цей крок, якщо в запиті є блок «Контекст запуску (диспетчер agent-flow)», або якщо команда нижче показана з незаміненими змінними `CLAUDE_…` чи файла скрипта немає (інший редактор). Виконай крок наприкінці роботи і на кожному шляху зупинки після взяття. Винятки: код `3` (задачу не взято) і втрачена задача (стан має лишитись, хіба що людина вирішила кинути задачу) — тоді `end` не виконуй:

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/kando-session" end --session "${CLAUDE_SESSION_ID}"
```

Результат команди не впливає на роботу.

## Заборонено

Мерджити, апрувити, force-push, змінювати базову гілку, виходити за межі зауважень, видаляти тести.
