# Політика розбору рев'ю

Політика за замовчуванням для скіла `review-triage`: що з зауважень AI-рев'ю виправляти,
що пропускати й що віддавати людині.

## Принципи

- PR має виходити чистим; не полірувати без кінця. Мета — без помилок і з тестами, а не ідеально.
- Виправляємо те, що ламає, і те, що дешево й безпечно виправити в межах дифу.
- Смак, рефакторинг «заодно» й дорогі дрібниці пропускаємо: людина бачить кожен пропуск у Kando
  і може не погодитися.
- Коли без продуктового рішення не обійтися — питаємо людину, а не вгадуємо.

## Правила

**P1** — `blocking` — виправити.
- Тест падає на граничному значенні; необроблений виняток на порожньому списку.
- PR робить більше, ніж просить тікет, і це рев'ю позначило блокуючим.

**P2** — `minor`, що виправляється локально в межах дифу, без зміни API й задуманої поведінки, — виправити.
- Незакритий файл чи зайвий `console.log` у новому коді.
- Опечатка в повідомленні про помилку, яке додав PR.

**P3** — немає тесту на нову поведінку — виправити.
- Нова гілка `if` для порожнього вводу без тесту.
- Виправлений баг без тесту, що падав би без фікса.

**P4** — смак без конвенції проєкту (назви, порядок, стиль, яких не вимагають лінтер, `CLAUDE.md` чи `AGENTS.md`) — пропустити.
- «Краще назвати `items`, а не `list`», а правила іменування в проєкті немає.
- «Перестав функції в алфавітному порядку».

**P5** — рефакторинг поза дифом PR — пропустити й запропонувати окрему задачу в причині.
- «Сусідній модуль теж варто перевести на async» — причина: «окрема задача: async у модулі X».
- «Винеси спільний код зі старих обробників».

**P6** — зміна ризикованіша за користь (багато файлів заради дрібниці) — пропустити.
- Перейменувати поле в десяти файлах заради однієї назви.
- Замінити залежність, щоб прибрати одне попередження.

**P7** — інше `minor`, якого не покриває жодне правило вище: потрібне продуктове рішення (вимоги,
API, поведінка для користувача) — людині; інакше — пропустити.
- «Може, показувати помилку тостом, а не під полем?» — людині.
- «Можна додати кешування» без вимірювань — пропустити.

## Порядок застосування

1. `blocking` — завжди P1.
2. `minor` — спершу правила «пропустити» (P4, P5, P6), потім «виправити» (P2, P3): дрібниця, що
   водночас локальна і смакова, — пропустити за P4.
3. Жодне не підійшло — P7.

## Своя політика репозиторію

Репозиторій може перевизначити політику файлом `.kando/review-policy.md`: правила з тими самими або новими id.
Файл репозиторію замінює цю політику повністю, тож скопіюй її й зміни потрібне. Не давай старому id
інший зміст: за id рішення зіставляють між колами й налаштовують політику з досвіду.
